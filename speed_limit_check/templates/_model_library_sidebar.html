{# The Model Registry Compare sidebar - included once from layout.html (not a per-page template) so it shows on every page without touching every existing route/template. A fixed-position overlay panel (not part of .wrap's centered flow) implementing a 4-step cascading picker - state -> period -> 2-3 tags -> a shared numeric column - each step scoped to what the previous step narrowed to, so this panel never lists the full calc_archive.model_registry_results table (see model_library.py's module docstring for why that matters at scale). Backed by /models/states, /models/periods, /models/tags, /models/columns, /models/compare. Also the ONE place that feeds a chosen model into every other tab ("that sidebar should feed all the tabs in this app" - explicit): a "Use this model" action per step-3 row writes {table, state, year_num, month_num, label} to localStorage and this same script applies it, on every page load, to whichever of #table/#state/#year/#month happen to exist on the current page. That connection is also surfaced IN the page's own content, not just inside this sidebar (renderPageModelNote()) - a screenshot of the live Quality page was real feedback that the relationship was invisible (the field silently changed with nothing on the page explaining why). On a GET-form page (Quality/Explore), clicking "Use" now navigates immediately - "Use" means use it now, not "remember this for later" - and a mismatched page offers a "show it here" link that does the same. On a POST-form page (Evaluator/Sign-checker, whose forms start a real run), nothing is ever auto-submitted - only the matching fields get filled in, with a note saying so. #}
