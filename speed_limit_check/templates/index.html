Image capture

0=N, 90=E, 180=S, 270=W. Applies to every position checked (centroid, walked positions, and side offsets alike). More headings costs one more Street View + Vision call per position each, but improves the odds of catching a sign at an angle that falls between the default four - e.g. try "0,45,90,135,180,225,270,315" for 8 directions.

When checked, each heading is rotated by the road's own local bearing at the position it's captured from (0=straight ahead along the road, 90=right, 180=behind, 270=left) instead of a fixed compass direction - useful since a sign usually faces along the road, not a specific compass point, and the road's bearing can vary along a walked segment.

Default {{ default_fov }} (Google's full-width shot). A narrower value zooms in, making a distant or small sign occupy more of the fixed image and so easier for OCR to read - try this if a sign is visibly in frame at the right position/heading but still isn't being detected. Comes at the cost of a narrower cone per heading, so a sign that was off to the side enough to still fit the default view may fall outside a much narrower one - pair a narrow zoom with more headings if a sign might be caught at an angle. Range {{ min_fov }}-{{ max_fov }}.

Walking options

The number of positions sampled is derived from this and each segment's actual length (2-40 points), rather than a fixed count - a short segment gets fewer, a long one gets more. Smaller spacing costs more API calls and runs slower; if a sign keeps getting missed, try a smaller value here.

A road can have two physically distinct, separately-surveyed-by-Google carriageways or trunks a short distance apart while sharing one here_segment_id - Street View's nearest-panorama snapping means centerline sampling alone can keep missing a sign on the other one. "Center only" checks just the position(s) themselves. "Sides only" offsets each position perpendicular to the road on both sides and skips the center entirely - useful once you know the center's own coverage isn't the carriageway/trunk you care about, since it wastes no calls on it. "Center + both sides" checks all three when you're not sure which one has the sign; roughly triples API calls per position.

If the other carriageway/trunk still isn't reached, try a larger offset.
